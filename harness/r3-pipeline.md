# 하네스 파이프라인

## 단계

```txt
S1 기획 검토 → S2 레퍼런스 → [G1] → S3 키스크린 → [G2] → S4 토큰·컴포넌트·화면 → [G3] → S5 가이드 판정
```

| 하네스 단계 | 원래 작업 단계 (`docs/story-work.md`) | 작업 주체 |
|---|---|---|
| S1 기획 검토 | 1 | 에이전트 |
| S2 레퍼런스 수집·분석 | 2 | 에이전트 (uibowl 커넥터) |
| S3 키스크린 | 3 (4 협의는 하네스 밖) | 에이전트 (Figma) |
| S4 토큰·컴포넌트·화면 | 5 | 에이전트 (Figma) |
| S5 가이드 판정 | 6 | 판정 스크립트 |

## 입출력

| 단계 | 입력 | 출력 |
|---|---|---|
| S1 | 대상 화면 이름, `docs/prd.md` | 화면 브리프: 화면 목적, 관련 유저스토리, 보여줄 데이터 필드, 권한별 차이, 상태값 |
| S2 | 화면 브리프 | 레퍼런스 분석: uibowl 화면 5~8개, 각각의 UX·UI 포인트, 반영할 것 |
| S3 | 화면 브리프, 레퍼런스 분석, `docs/design.md` | Figma `02 Screens` › `Key Screens`에 390×844 키스크린 2~3개 + 스냅샷 |
| S4 | 승인된 키스크린, `docs/design.md` | Figma `03 Tokens & Components`, `02 Screens` › `Screens`에 대상 화면 1개 + 스냅샷 |
| S5 | S4 스냅샷, `docs/design.md`, `docs/story-service.md`의 A·B | 판정 결과: 위반 목록, 위반 수 |

## 되돌아가는 지점

| 상황 | 돌아가는 곳 |
|---|---|
| G1 반려 | S2 |
| G2 반려 | S3 |
| G3 반려 | S4 |
| S5 위반 1건 이상 | S4 (위반 항목만 수정) |

## 재시도 한도

- 한 단계당 3회. 3회째에도 통과하지 못하면 자동 재시도를 멈추고 나에게 넘긴다.
