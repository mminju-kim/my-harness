# 하네스 검증과 리뷰

## 1. 판정 스크립트 검증 (실제 실행 전)

- 위치: `harness/tests/fixtures/`
- 깨끗한 샘플 → judge 위반 0건
- 위반 샘플 16개 → 판정 id마다 1개, 그 규칙만 일부러 어김
  `M1 M2 M3 / D1 D2 D3 D4 D5 D6 D7 D8 / A1 A2 / B1 B2 B3`
  → 각 샘플에서 그 id만 정확히 1건 걸려야 한다
- 통과 기준: 모든 샘플이 기대값과 일치. 1개라도 다르면 `judge.py`를 고치고 다시 돌린다.

## 2. 첫 리허설

- 대상 화면: `my-assets` (내 자산)
- 이유: 판정 A(기본 비공개)와 B3(민감정보)가 함께 걸리고, 자산 등록 → 판매 신청 흐름이 들어 있다.

## 3. 리허설 리뷰

`harness/r8-review.md`에 아래 숫자를 기록한다.

| 항목 | 이 숫자가 나오면 |
|---|---|
| 단계별 재시도 횟수 | 3회 도달이 1번이라도 있으면 해당 에이전트 지시문 수정 |
| G 반려 수와 사유 | 같은 사유 2번 이상이면 기계 판정 조건으로 옮길지 검토 |
| S5 위반 id별 건수 | 같은 id가 반복되면 `screen-designer` 지시문에 그 규칙 추가 |
| 승인 없이 다음 단계로 넘어간 횟수 | 1번이라도 있으면 R7에서 미룬 훅 추가 |

## 4. 만드는 순서

1. `harness/rules.json`: R5 값 그대로
2. `harness/scripts/judge.py` + 샘플 → 1번 검증 통과 확인
3. `.claude/agents/` 서브에이전트 5개
4. `CLAUDE.md`: 초안 승인 후 생성
5. Figma 작업 파일 생성 + `harness/figma.json` (만들기 직전에 한 번 더 확인)
6. `.claude/settings.json` 권한 설정 (마지막)
7. `my-assets` 리허설 → `harness/r8-review.md`
